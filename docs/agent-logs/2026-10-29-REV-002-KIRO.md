## Decisions and alternatives
- LCP root cause, from Lighthouse 13.6 Lantern source (node_modules/@paulirish/trace_engine/models/trace/lantern/metrics/LargestContentfulPaint.js and FirstContentfulPaint.js): simulated LCP = max end time of all non-low-priority-image nodes that finished before the observed LCP, including async scripts whose EvaluateScript started before it. Locally, Next chunks (~148 KB: 72 KB + 46 KB framework, rest app/runtime) download in <100 ms and evaluate before the first paint, so they are always in the graph. FCP graph excludes them (0.9 s), LCP includes them (2.8 s).
- Diagnostic (not shipped): stripping external script tags from a throwaway out/index.html gave mobile LCP 1580 ms (1 run). out/ was rebuilt afterwards and verified to contain 8 script tags again.
- Rejected: experimental.inlineCss. Next docs mark it experimental and not recommended for production (https://nextjs.org/docs/app/api-reference/config/next-config-js/inlineCss), and the ~3.7 KB CSS is not on the critical path that sets LCP.
- Rejected: making the H1 the LCP element (Lantern uses the FCP graph for text LCP). That games the metric and changes the design.
- Not done, needs user decision + ADR: delaying Next hydration scripts until after the hero image loads (post-export HTML transform), or replacing React hydration for SiteMenu/MotionEnhancer. Both change architectural boundaries and trade interactivity timing for lab LCP.
